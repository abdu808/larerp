# قواعد قبول عمل الوكلاء والموديولات

## المبدأ

كل موديول يتم تسليمه كقطعة مستقلة قابلة للتشغيل والاختبار. لا يقبل أي عمل لمجرد أن الكود كتب أو الملفات أضيفت؛ القبول يكون بعد المراجعة والتجربة.

## نطاق كل وكيل

- يستلم الوكيل موديولا محددا بملفات واضحة.
- لا يغير ملفات موديول آخر إلا عند ضرورة واضحة ويذكر السبب في تقريره.
- لا يضيف حزم Composer أو npm إلا إذا كانت الحاجة قوية ومذكورة.
- لا يغير قرارات المعمارية العامة بدون موافقة قائد التطوير.

## الحد الأدنى لتسليم أي موديول

- Migrations صحيحة وقابلة للتشغيل.
- Models بعلاقات Eloquent واضحة.
- Filament Resources باللغة العربية لإدارة البيانات الأساسية.
- Seeders عند الحاجة لبيانات تجربة.
- Tests تغطي الإنشاء أو العلاقات أو صلاحيات الوصول الأساسية.
- لا توجد أخطاء تنسيق من Pint.
- لا توجد اختبارات فاشلة.

## أوامر القبول الإلزامية

قبل قبول أي تسليم يجب أن تنجح الأوامر التالية:

```bash
php artisan migrate:fresh --seed
php artisan test
php vendor/bin/pint --test
```

وعند وجود تغييرات في الواجهة أو assets:

```bash
npm run build
```

## تقرير الوكيل

يجب أن يحتوي تقرير كل وكيل على:

- اسم الموديول.
- الملفات التي عدلها أو أضافها.
- القرارات التي اتخذها.
- أوامر التحقق التي شغلها.
- نتيجة الاختبارات.
- القيود أو الافتراضات.

## دور قائد التطوير

قائد التطوير يراجع مخرجات الوكلاء ولا يدمج إلا المقبول. عند وجود نقص يرجع العمل للوكيل أو يعالجه مركزيا مع توثيق السبب.

## قاعدة مهمة

السرعة مطلوبة، لكن القبول مشروط بالتجربة. أي موديول لا يمر بالاختبار والمراجعة يعتبر غير مكتمل حتى لو كان شكله جاهزا.

# مصفوفة تنفيذ موديولات منصة ERP للجمعيات

الإصدار: 0.1  
مرتبطة بالوثيقة: `charity-erp-platform-blueprint-ar.md`  
الغرض: تحويل الرؤية العامة إلى وحدات عمل قابلة للتوزيع على مطورين أو وكلاء AI.

---

## 1. طريقة استخدام هذه المصفوفة

هذه المصفوفة لا تستبدل الوثيقة المرجعية، بل تكملها.  
الوثيقة المرجعية تحدد القرار المعماري والمنتج النهائي.  
هذه المصفوفة تحدد ماذا يستلم كل مطور وماذا يجب أن يسلم.

نموذج العمل المعتمد:

**قائد تطوير مركزي + وكلاء متخصصون لكل موديول داخل نفس المشروع**

القائد المركزي مسؤول عن:

- بناء Foundation أو الإشراف المباشر عليه.
- تثبيت conventions.
- تحديد حدود كل موديول.
- توزيع المهام على الوكلاء.
- مراجعة مخرجات كل وكيل.
- دمج التغييرات النهائية.
- حل التعارضات بين الموديولات.

الوكلاء المتخصصون لا يعملون كمشاريع مستقلة، بل يعملون داخل نفس المشروع وضمن حدود الموديول المكلفين به.

عند تكليف مطور أو وكيل AI:

- يعطى موديول واحد أو Workstream واحد فقط.
- يلتزم بالجداول والشاشات والقواعد المذكورة هنا.
- لا يغير قرارات التقنية أو النشر.
- لا يبني موديولا بلا صلاحيات واختبارات أساسية.
- لا يضيف اعتمادا على موديول آخر بدون توثيق نقطة الربط.
- لا يدمج عمله مباشرة بدون مراجعة القائد المركزي.

---

## 2. قواعد التسليم لكل موديول

كل موديول يجب أن يسلم بالحد الأدنى التالي:

- Migrations.
- Models.
- Relationships.
- Policies.
- Filament Resources.
- Forms.
- Tables and Filters.
- Seeders عند الحاجة.
- Tests للقواعد الحرجة.
- Audit Log للعمليات الحساسة.
- Notes مختصرة عن قرارات التنفيذ.

يمنع اعتبار الموديول مكتملا إذا كان CRUD فقط بدون قواعد عمل أو صلاحيات.

## 3. مصفوفة الموديولات

### 3.1 Platform Foundation

الهدف:

بناء أساس Laravel الذي تعتمد عليه كل الموديولات.

الملكية:

فريق الأساس فقط. لا يحق لباقي الفرق تعديل قراراته إلا بمراجعة.

النطاق:

- إعداد Laravel.
- إعداد PostgreSQL.
- إعداد Filament.
- المصادقة.
- الأدوار والصلاحيات.
- إعدادات الجمعية.
- سجل التدقيق.
- الإشعارات.
- إعداد القوالب العامة.

الجداول:

- organizations
- branches
- users
- roles
- permissions
- role_user
- system_settings
- audit_logs
- notifications
- login_logs

الشاشات:

- إعدادات الجمعية.
- المستخدمون.
- الأدوار.
- الصلاحيات.
- الفروع.
- سجل التدقيق.
- الإشعارات.

قواعد العمل:

- لا يوجد مستخدم بلا دور.
- لا يتم تفعيل موديول بلا صلاحية مقابلة.
- كل عملية حساسة تحفظ في Audit Log.
- إعدادات الجمعية لا تخلط داخل الكود، بل تحفظ في قاعدة البيانات أو ملف إعداد واضح.

يعتمد عليه:

كل الموديولات.

معايير القبول:

- يمكن تسجيل الدخول للوحة Filament.
- يمكن إنشاء مستخدم ودور.
- يمكن منع مستخدم من شاشة لا يملك صلاحيتها.
- يمكن تعديل إعدادات الجمعية.
- يتم تسجيل عمليات الإنشاء والتعديل والحذف الحساسة.

- أي وثيقة لها مالك أو سياق.
- يمكن ربط الوثيقة بأكثر من كيان.
- الوثائق الحساسة لا تظهر إلا بصلاحية.
- الإحالة لها مسؤول وموعد وحالة.

يرتبط مع:

- كل الموديولات تقريبا.

معايير القبول:

- يمكن رفع وثيقة.
- يمكن تصنيفها.
- يمكن ربطها بمستفيد أو مشروع.
- يمكن إنشاء وارد أو صادر وإحالته.

# خطة تنفيذ مسار الحوكمة والمجلس والموارد البشرية الأساسية والوثائق والأرشيف والمراسلات

## 1. الهدف والنطاق

يهدف هذا المسار إلى بناء منظومة إدارية داخلية في Laravel + Filament + PostgreSQL لإدارة الحوكمة المؤسسية، مجلس الإدارة، اللجان، الاجتماعات، القرارات، السياسات، المخاطر، الإفصاحات، الوثائق، الأرشيف، المراسلات، العقود، والبيانات الأساسية للموارد البشرية. الغرض من المسار هو توفير سجل موثق وقابل للتدقيق لكل ما يتعلق بالإدارة النظامية والامتثال، مع واجهات تشغيل واضحة في Filament وصلاحيات دقيقة تمنع الوصول غير المصرح به.

لا يتضمن هذا المستند إنشاء كود Laravel أو Filament. هو خطة تنفيذ وظيفية وفنية لتوجيه التطوير لاحقا.

يشمل النطاق:

- أعضاء مجلس الإدارة ومناصبهم ودوراتهم.
- اللجان النظامية والتنفيذية وعضوياتها.
- الاجتماعات ومحاضرها وجدول أعمالها والحضور.
- القرارات والتوصيات ومتابعة تنفيذها.
- السياسات واللوائح الداخلية وإصداراتها واعتماداتها.
- سجل المخاطر والإجراءات التصحيحية.
- الإفصاحات وتعارض المصالح والإقرارات.
- إدارة الوثائق والأرشفة والتصنيف وفترات الحفظ.
- المراسلات الصادرة والواردة والداخلية.
- العقود والاتفاقيات ومواعيد التجديد والانتهاء.
- الموارد البشرية الأساسية: الموظفون، المناصب، الإدارات، الملفات الوظيفية، الإجازات أو الطلبات البسيطة عند الحاجة.
- الصلاحيات، التدقيق، الاختبارات، ومعايير القبول.
- التكامل مع الموقع العام Public Website والتقارير Reports.

خارج النطاق في هذا المسار:

- الرواتب ومسير الأجور والحسابات المالية التفصيلية.
- نظام موارد بشرية متقدم يشمل تقييم الأداء، الحضور والانصراف، التأمينات، أو كشوف المرتبات.
- التوقيع الإلكتروني القانوني المتقدم إلا كنقطة تكامل مستقبلية.
- الأتمتة الخارجية للبريد أو الرسائل النصية إلا من خلال نقاط ربط قابلة للتوسعة.
- نشر محتوى الموقع العام فعليا، إذ يقتصر المسار على تجهيز البيانات التي قد يستهلكها الموقع.

## 2. المبادئ العامة للتنفيذ

- اعتماد PostgreSQL كمصدر الحقيقة لكل السجلات النظامية، مع حفظ المرفقات في تخزين ملفات منظم ومربوط بالكيانات.
- جعل Filament واجهة التشغيل الرئيسية للإداريين، السكرتارية، الموارد البشرية، مسؤولي الحوكمة، ومديري الإدارات.
- الفصل بين السجل الإداري التشغيلي والسجل المنشور للعامة؛ لا ينشر أي محتوى على الموقع العام إلا بعد اعتماد صريح.
- حفظ تاريخ الإصدارات للسياسات والوثائق والعقود والقرارات المهمة.
- تطبيق مبدأ أقل صلاحية ممكنة، خصوصا في ملفات الموظفين، الإفصاحات، العقود، والمراسلات الحساسة.
- عدم حذف السجلات النظامية حذفا نهائيا إلا وفق سياسة أرشفة وحفظ معتمدة؛ يفضل التعطيل أو الأرشفة أو الحذف الناعم.
- ربط كل قرار أو سياسة أو عقد أو مخاطبة بمالك واضح ومسؤول متابعة وتواريخ استحقاق.
- تصميم كل شاشة بحيث تدعم البحث، التصفية، التصدير، وعرض سجل التدقيق عند الحاجة.
- توحيد حالات العمل بين الكيانات: مسودة، قيد المراجعة، معتمد، منشور، مؤرشف، ملغي، منتهي.

## 3. الكيانات الأساسية ونموذج البيانات المقترح

### 3.1 أعضاء مجلس الإدارة

الغرض هو توثيق بيانات أعضاء المجلس ودورات العضوية والمناصب الرسمية وسجل الإفصاحات.

البيانات المقترحة:

- الاسم الكامل.
- الصفة: رئيس، نائب رئيس، عضو، أمين سر، مستشار.
- رقم الهوية أو مرجع تعريف داخلي حسب سياسة الخصوصية.
- بيانات التواصل الرسمية.
- تاريخ بداية العضوية وتاريخ نهايتها.
- دورة المجلس المرتبطة.
- حالة العضوية: نشط، منتهية، مستقيل، معفى، مجمد.
- السيرة المختصرة القابلة للنشر.
- صورة شخصية اختيارية قابلة للنشر.
- قابل للنشر في الموقع العام: نعم أو لا.
- ملاحظات داخلية.

العلاقات:

- يرتبط العضو بدورة مجلس واحدة أو أكثر.
- يمكن أن يكون عضوا في لجان متعددة.
- يمكن أن يحضر اجتماعات متعددة.
- يمكن أن تكون له إفصاحات وتعارض مصالح.
- يمكن أن يرتبط بقرارات من حيث الاقتراح أو التصويت أو التكليف.

### 3.2 دورات المجلس والمناصب

الغرض هو فصل الشخص عن مدة ولايته ومنصبه حتى يمكن حفظ التاريخ المؤسسي بدقة.

البيانات المقترحة:

- اسم الدورة.
- تاريخ البداية والنهاية.
- رقم القرار أو مرجع الاعتماد.
- حالة الدورة: مخطط لها، نشطة، منتهية، مؤرشفة.
- المرفقات النظامية.
- ملاحظات.

متطلبات التنفيذ:

- منع وجود أكثر من دورة نشطة إذا كانت سياسة الجمعية لا تسمح بذلك.
- إظهار أعضاء الدورة الحالية في لوحة الحوكمة.
- الاحتفاظ بالدورات السابقة لأغراض التقارير والتدقيق.

### 3.3 اللجان

تشمل اللجان الدائمة والمؤقتة مثل لجنة المراجعة، لجنة الاستثمار، لجنة الترشيحات، لجنة المشتريات، أو لجان دراسة الحالات حسب احتياج الجمعية.

البيانات المقترحة:

- اسم اللجنة.
- نوع اللجنة: مجلس، تنفيذية، رقابية، مؤقتة.
- اختصاص اللجنة.
- تاريخ التشكيل والانتهاء.
- قرار التشكيل.
- الرئيس والمقرر والأعضاء.
- حالة اللجنة.
- قابل للنشر: نعم أو لا.
- مرفقات التشكيل واللوائح.

العلاقات:

- اللجنة لها أعضاء من المجلس أو الموظفين أو أطراف خارجية.
- اللجنة لها اجتماعات ومحاضر وقرارات.
- اللجنة يمكن أن تكون مالكة لمخاطر أو سياسات أو توصيات.

### 3.4 الاجتماعات

الغرض هو إدارة دورة الاجتماع كاملة من الدعوة إلى الاعتماد والمتابعة.

البيانات المقترحة:

- نوع الاجتماع: مجلس إدارة، لجنة، إدارة تنفيذية، موارد بشرية، آخر.
- الجهة المرتبطة: مجلس أو لجنة أو إدارة.
- العنوان.
- التاريخ والوقت والمكان أو رابط الاجتماع.
- الحالة: مجدول، منعقد، بانتظار المحضر، بانتظار الاعتماد، معتمد، ملغي.
- جدول الأعمال.
- الحضور والاعتذارات.
- محضر الاجتماع.
- المرفقات.
- نسبة اكتمال بنود المتابعة.

متطلبات Filament:

- شاشة قائمة مع فلاتر حسب النوع والحالة والتاريخ والجهة.
- شاشة إنشاء اجتماع من قالب اختياري.
- إدارة الحضور من جدول فرعي داخل صفحة الاجتماع.
- إدارة بنود جدول الأعمال والقرارات من نفس الصفحة أو صفحات مرتبطة.
- إجراء اعتماد المحضر بصلاحية محددة.

### 3.5 القرارات والتوصيات

الغرض هو تحويل مخرجات الاجتماعات إلى سجل قابل للمتابعة.

البيانات المقترحة:

- رقم القرار أو الرمز الداخلي.
- عنوان القرار.
- نص القرار.
- مصدر القرار: اجتماع، لجنة، مجلس، إدارة.
- تاريخ القرار.
- مستوى الأهمية.
- الحالة: مسودة، معتمد، قيد التنفيذ، منفذ، متعثر، ملغي، مؤرشف.
- المسؤول عن التنفيذ.
- تاريخ الاستحقاق.
- نسبة الإنجاز.
- ملاحظات المتابعة.
- مرفقات داعمة.
- قابل للنشر في الموقع العام عند الحاجة.

متطلبات المتابعة:

- سجل تحديثات لكل قرار.
- تنبيهات داخلية للقرارات المتأخرة.
- تقرير قرارات مفتوحة حسب المسؤول والجهة.
- ربط القرارات بالسياسات أو العقود أو المخاطر عند وجود أثر مباشر.

### 3.6 السياسات واللوائح

الغرض هو إدارة وثائق الحوكمة الرسمية مثل سياسة الخصوصية، سياسة تعارض المصالح، لائحة الموارد البشرية، لائحة المشتريات، سياسة قبول التبرعات، وسياسة الاحتفاظ بالوثائق.

البيانات المقترحة:

- اسم السياسة.
- التصنيف.
- المالك الإداري.
- رقم الإصدار.
- تاريخ الاعتماد.
- تاريخ السريان.
- تاريخ المراجعة القادمة.
- الحالة: مسودة، قيد المراجعة، معتمدة، منشورة، مستبدلة، مؤرشفة.
- الجهة المعتمدة.
- ملف السياسة.
- ملخص قابل للنشر.
- قابل للنشر في الموقع العام.

متطلبات الإصدارات:

- كل تعديل جوهري ينشئ إصدارا جديدا.
- الاحتفاظ بالإصدارات السابقة مع تاريخ الاستبدال.
- منع تعديل الإصدار المعتمد مباشرة دون إنشاء مسودة جديدة.
- ربط السياسة بقرارات الاعتماد والمخاطر ذات العلاقة.

### 3.7 المخاطر

الغرض هو سجل مخاطر مبسط يدعم الحوكمة والرقابة، دون بناء نظام GRC متقدم في المرحلة الأولى.

البيانات المقترحة:

- عنوان الخطر.
- الوصف.
- المجال: حوكمة، مالي، تشغيلي، تقني، قانوني، سمعة، موارد بشرية.
- الاحتمالية.
- الأثر.
- مستوى الخطر المحسوب.
- مالك الخطر.
- خطة المعالجة.
- تاريخ المراجعة القادمة.
- الحالة: مفتوح، تحت المعالجة، مقبول، مغلق، متصاعد.
- ارتباط بسياسة أو قرار أو عقد أو حادثة.

متطلبات التشغيل:

- مصفوفة مخاطر بسيطة في التقارير.
- فلاتر حسب المستوى والمالك والحالة.
- سجل إجراءات معالجة ومتابعة.
- تنبيه للمخاطر التي تجاوزت تاريخ المراجعة.

### 3.8 الإفصاحات وتعارض المصالح

الغرض هو إدارة إقرارات الأعضاء والموظفين ومنسوبي اللجان حول المصالح والعلاقات ذات الصلة.

البيانات المقترحة:

- الشخص المرتبط: عضو مجلس، موظف، عضو لجنة، طرف خارجي.
- نوع الإفصاح: سنوي، متعلق بقرار، متعلق بعقد، طارئ.
- موضوع الإفصاح.
- وصف المصلحة أو التعارض.
- مستوى الحساسية.
- الحالة: مقدم، قيد المراجعة، مقبول، يتطلب إجراء، مغلق.
- الجهة المراجعة.
- القرار أو العقد المرتبط إن وجد.
- المرفقات.

ضوابط مهمة:

- تقييد الوصول إلى الإفصاحات الحساسة.
- إظهار تنبيه عند ربط شخص بقرار أو عقد وله إفصاح نشط ذي صلة.
- حفظ سجل مراجعة الإفصاح والنتيجة.

### 3.9 الوثائق والأرشيف

الغرض هو توفير سجل مركزي للوثائق الرسمية والقابلة للتصنيف، مع ربط الوثيقة بالكيان المناسب.

البيانات المقترحة:

- عنوان الوثيقة.
- رقم الوثيقة أو الرمز.
- التصنيف: حوكمة، مجلس، لجنة، موارد بشرية، عقد، مراسلة، مالي، نظامي، آخر.
- الكيان المرتبط اختياريا.
- مالك الوثيقة.
- مستوى السرية: عام، داخلي، سري، سري جدا.
- تاريخ الإنشاء أو الاستلام.
- تاريخ الاعتماد.
- تاريخ انتهاء الصلاحية إن وجد.
- فترة الحفظ.
- حالة الأرشفة.
- الملف أو الملفات المرفقة.
- كلمات مفتاحية.

متطلبات الأرشفة:

- دعم البحث بالعنوان والرقم والكلمات المفتاحية والتصنيف.
- منع نشر أو تحميل الوثائق السرية إلا لصلاحيات محددة.
- دعم أرشفة الوثائق المنتهية مع بقائها قابلة للاسترجاع.
- توثيق سبب الحذف أو الإلغاء عند حدوثه.
- ربط الوثائق بالمراسلات والعقود والاجتماعات والسياسات.

### 3.10 المراسلات

الغرض هو إدارة الخطابات الصادرة والواردة والداخلية ومتابعة الردود.

البيانات المقترحة:

- رقم المراسلة.
- النوع: وارد، صادر، داخلي.
- الجهة المرسلة.
- الجهة المستقبلة.
- الموضوع.
- تاريخ المراسلة.
- تاريخ الاستلام أو الإرسال.
- قناة المراسلة: بريد إلكتروني، خطاب ورقي، منصة حكومية، تسليم يدوي، أخرى.
- الحالة: مسودة، مرسلة، واردة، بانتظار رد، مغلقة، مؤرشفة.
- درجة السرية.
- المسؤول الداخلي.
- تاريخ الاستحقاق للرد.
- ملخص.
- المرفقات.
- مراسلة أصلية أو رد على مراسلة.

متطلبات التشغيل:

- تسلسل واضح لأرقام المراسلات حسب السنة والنوع.
- ربط المراسلات بالعقود أو القرارات أو المستفيدين أو المشاريع عند الحاجة، دون نقل ملكية تلك الكيانات لهذا المسار.
- قائمة مراسلات متأخرة أو بانتظار رد.
- إمكانية تصدير سجل المراسلات للتقارير.

### 3.11 العقود والاتفاقيات

الغرض هو إدارة العقود والاتفاقيات ومذكرات التفاهم من منظور إداري وأرشيفي، مع ترك الأثر المالي التفصيلي لمسار المالية.

البيانات المقترحة:

- اسم العقد.
- نوع العقد: مورد، شراكة، موظف، إيجار، خدمة، مذكرة تفاهم، آخر.
- الطرف الآخر.
- رقم العقد.
- تاريخ البداية والنهاية.
- قيمة العقد إن وجدت.
- العملة.
- الحالة: مسودة، قيد المراجعة، نشط، قارب الانتهاء، منتهي، مجدد، ملغي.
- مالك العقد.
- الجهة المستفيدة داخليا.
- شروط التجديد.
- تاريخ التنبيه قبل الانتهاء.
- المرفقات والإصدارات.
- ارتباط بالمراسلات أو القرارات أو المخاطر.

متطلبات مهمة:

- تنبيه العقود التي تقترب من الانتهاء.
- حفظ نسخة معتمدة ونسخ مراجعة عند الحاجة.
- تقييد العقود ذات القيمة أو الحساسية العالية.
- توفير حقول تسمح لمسار التقارير بعرض الالتزامات والتواريخ دون كشف الملفات السرية.

### 3.12 الموارد البشرية الأساسية

الغرض هو توفير الحد الأدنى من بيانات الموظفين اللازمة للتشغيل والصلاحيات والمراسلات والتكليفات، دون بناء نظام HR كامل.

الكيانات المقترحة:

- الموظفون.
- الإدارات.
- المناصب أو المسميات الوظيفية.
- أنواع العقود الوظيفية.
- ملفات الموظفين الأساسية.
- طلبات بسيطة اختيارية مثل خطاب تعريف أو إجازة إدارية، إذا كانت مطلوبة في المرحلة الأولى.

بيانات الموظف المقترحة:

- الاسم الكامل.
- رقم الموظف.
- بيانات التواصل.
- الإدارة.
- المسمى الوظيفي.
- المدير المباشر.
- تاريخ الالتحاق.
- حالة الموظف: نشط، تحت التجربة، موقوف، مستقيل، منتهي الخدمة.
- نوع العلاقة: موظف، متعاون، متطوع إداري، مستشار.
- حساب المستخدم المرتبط إن وجد.
- مرفقات أساسية مثل العقد أو الهوية حسب سياسة الخصوصية.

ضوابط:

- فصل بيانات الموظف العامة عن الملفات الحساسة.
- عدم إتاحة ملفات الموظفين إلا لموارد بشرية أو إدارة مصرح لها.
- استخدام بيانات الموظفين في إسناد القرارات، المخاطر، العقود، والمراسلات.

## 4. واجهات Filament المقترحة

الموارد الأساسية:

- BoardMemberResource لإدارة أعضاء المجلس.
- BoardTermResource لإدارة دورات المجلس.
- CommitteeResource لإدارة اللجان.
- MeetingResource لإدارة الاجتماعات.
- DecisionResource لإدارة القرارات.
- PolicyResource لإدارة السياسات واللوائح.
- RiskResource لإدارة المخاطر.
- DisclosureResource لإدارة الإفصاحات.
- DocumentResource لإدارة الوثائق والأرشيف.
- CorrespondenceResource لإدارة المراسلات.
- ContractResource لإدارة العقود.
- EmployeeResource لإدارة بيانات الموارد البشرية الأساسية.
- DepartmentResource وJobTitleResource للبيانات المرجعية.

لوحات العمل:

- لوحة حوكمة تعرض الاجتماعات القادمة، القرارات المتأخرة، السياسات التي تحتاج مراجعة، والمخاطر العالية.
- لوحة أرشيف تعرض أحدث الوثائق، الوثائق المنتهية، والمراسلات بانتظار رد.
- لوحة موارد بشرية أساسية تعرض الموظفين النشطين، العقود الوظيفية القريبة من الانتهاء، والملفات الناقصة.

متطلبات تجربة المستخدم:

- استخدام تبويبات داخل صفحة الكيان عند وجود علاقات كثيرة مثل اجتماع مع الحضور والقرارات والمرفقات.
- استخدام شارات حالة ملونة وموحدة بين الموارد.
- دعم البحث العام داخل كل مورد.
- توفير فلاتر متقدمة حسب التاريخ والحالة والجهة والسرية والمالك.
- توفير إجراءات صفية مثل اعتماد، أرشفة، إلغاء، إنشاء إصدار جديد، إغلاق، أو تعيين مسؤول.

## 5. الصلاحيات والأدوار

الأدوار المقترحة:

- Super Admin: إدارة كاملة.
- Governance Manager: إدارة الحوكمة والمجلس واللجان والسياسات والمخاطر.
- Board Secretary: إدارة الاجتماعات والمحاضر والقرارات والمراسلات الخاصة بالمجلس.
- HR Officer: إدارة بيانات الموظفين وملفات الموارد البشرية الأساسية.
- Archive Officer: إدارة الوثائق والأرشيف والمراسلات.
- Department Manager: عرض وتحديث العناصر المسندة لإدارته.
- Report Viewer: عرض تقارير محددة دون تعديل.
- Public Content Publisher: مراجعة العناصر القابلة للنشر للموقع العام.
- Auditor: قراءة سجلات محددة وسجل التدقيق دون تعديل.

مصفوفة صلاحيات مختصرة:

- أعضاء المجلس واللجان: عرض للحوكمة، تعديل للحوكمة، قراءة محدودة للمدقق.
- الاجتماعات والقرارات: إنشاء وتعديل للسكرتارية والحوكمة، اعتماد حسب دور أعلى.
- السياسات: إنشاء مسودة للحوكمة، اعتماد لصلاحية مخصصة، نشر لصلاحية نشر.
- المخاطر: إنشاء وتحديث للحوكمة والمالكين، إغلاق لصلاحية أعلى.
- الإفصاحات: إنشاء للشخص أو الموظف المخول، مراجعة للحوكمة أو الامتثال، وصول محدود جدا.
- الوثائق السرية والعقود: وصول مقيد حسب السرية والمالك.
- الموارد البشرية: وصول كامل للموارد البشرية، قراءة محدودة للمدير المباشر حسب الحاجة.

متطلبات أمنية:

- استخدام Policies لكل كيان مهم.
- تسجيل عمليات الإنشاء والتعديل والاعتماد والأرشفة والحذف الناعم.
- منع تعديل السجلات المعتمدة إلا عبر سير إصدار أو إجراء إعادة فتح بصلاحية خاصة.
- منع تنزيل الملفات الحساسة من مستخدمين لا يملكون صلاحية مشاهدة الملف نفسه.

## 6. سير العمل الأساسي

### 6.1 اجتماع مجلس أو لجنة

1. تنشئ السكرتارية الاجتماع وتحدد الجهة والتاريخ وجدول الأعمال.
2. تضاف الدعوات والحضور المتوقعون.
3. بعد الاجتماع تسجل الحضور والاعتذارات ومحضر الاجتماع.
4. تحول البنود إلى قرارات أو توصيات عند الحاجة.
5. يراجع صاحب الصلاحية المحضر ويعتمده.
6. تبدأ متابعة القرارات مع مسؤول وتاريخ استحقاق.
7. تؤرشف نسخة المحضر والمرفقات ضمن الوثائق.

### 6.2 سياسة أو لائحة

1. تنشئ الحوكمة مسودة سياسة.
2. ترفق نسخة العمل وتحدد المالك والمراجع وتاريخ المراجعة.
3. ترفع للجهة المعتمدة وترتبط بقرار اعتماد.
4. بعد الاعتماد تصبح نسخة معتمدة غير قابلة للتعديل المباشر.
5. إذا كانت قابلة للنشر، تظهر ضمن قائمة انتظار النشر للموقع العام.
6. عند التعديل لاحقا، ينشأ إصدار جديد مع بقاء الإصدار السابق مؤرشيفا.

### 6.3 مراسلة واردة أو صادرة

1. يسجل مسؤول الأرشيف المراسلة برقم ونوع وجهة وموضوع.
2. ترفق الملفات وتحدد درجة السرية والمسؤول الداخلي.
3. إذا تطلبت ردا، يحدد تاريخ استحقاق.
4. يمكن ربطها بعقد أو قرار أو وثيقة أو جهة.
5. تغلق عند اكتمال الإجراء أو الرد.
6. تحفظ في الأرشيف وفق التصنيف وفترة الحفظ.

### 6.4 عقد أو اتفاقية

1. ينشأ سجل عقد في حالة مسودة أو قيد المراجعة.
2. تضاف الأطراف والتواريخ والقيمة والمالك الداخلي.
3. ترفق النسخ والمراسلات ذات العلاقة.
4. بعد الاعتماد يصبح العقد نشطا.
5. تظهر تنبيهات قبل الانتهاء حسب تاريخ التنبيه.
6. عند التجديد أو الإنهاء يحفظ الإجراء في سجل العقد.

## 7. التكامل مع Public Website

يجب أن يكون التكامل مع الموقع العام اختياريا ومحكوما بصلاحية نشر، ولا يسمح بسحب البيانات الداخلية مباشرة دون مراجعة.

البيانات المحتملة للنشر:

- أعضاء مجلس الإدارة الحاليون مع السيرة المختصرة والصورة عند تفعيل قابل للنشر.
- اللجان العامة المعتمدة إن كانت سياسة الجمعية تسمح بذلك.
- السياسات واللوائح المنشورة للعامة.
- التقارير أو القرارات العامة التي تقرر الجمعية نشرها.
- بيانات الحوكمة الأساسية مثل أسماء الدورات أو نبذة عن المجلس.

متطلبات التكامل:

- حقول `is_public` أو ما يعادلها لكل كيان قابل للنشر.
- حقل ملخص عام منفصل عن الملاحظات الداخلية.
- حالة نشر: غير منشور، بانتظار مراجعة، منشور، مسحوب.
- API أو طبقة قراءة مخصصة للموقع العام لا تكشف الملفات السرية أو الحقول الداخلية.
- سجل يوضح من اعتمد نشر المحتوى ومتى.
- عند أرشفة سياسة منشورة أو استبدالها، يجب تحديث حالة النشر أو إظهار الإصدار الأحدث فقط.

معايير القبول للتكامل:

- لا يظهر على الموقع العام أي عضو أو سياسة أو وثيقة دون تفعيل النشر والاعتماد.
- البيانات المنشورة لا تحتوي ملاحظات داخلية أو أرقام هوية أو ملفات سرية.
- يمكن للموقع العام عرض قائمة السياسات المنشورة وأعضاء المجلس الحاليين من مصدر منظم.

## 8. التكامل مع Reports

يجب تجهيز هذا المسار بمؤشرات ومخرجات يمكن لمسار التقارير استخدامها دون نسخ المنطق داخله.

التقارير المطلوبة:

- تقرير أعضاء المجلس حسب الدورة والحالة.
- تقرير اللجان وأعضائها واجتماعاتها.
- تقرير الاجتماعات حسب الفترة والجهة ونسبة اكتمال المحاضر.
- تقرير القرارات المفتوحة والمتأخرة والمنفذة.
- تقرير السياسات التي تحتاج مراجعة خلال فترة محددة.
- تقرير المخاطر حسب المستوى والمالك والحالة.
- تقرير الإفصاحات حسب الحالة والنوع دون كشف التفاصيل الحساسة لغير المخولين.
- تقرير الوثائق حسب التصنيف والسرية وفترة الحفظ.
- تقرير المراسلات بانتظار رد أو المتأخرة.
- تقرير العقود النشطة والقريبة من الانتهاء والمنتهية.
- تقرير الموظفين الأساسي حسب الإدارة والحالة ونوع العلاقة.

متطلبات البيانات للتقارير:

- توحيد أسماء الحالات والقيم المرجعية.
- وجود تواريخ واضحة للإنشاء والاعتماد والانتهاء والاستحقاق.
- استخدام علاقات مباشرة بدلا من نصوص حرة كلما أمكن.
- توفير نطاقات قراءة آمنة تراعي الصلاحيات.
- عدم إظهار روابط ملفات سرية في تقارير عامة أو تقارير منخفضة الصلاحية.

## 9. الاختبارات المطلوبة

اختبارات البيانات والعلاقات:

- إنشاء عضو مجلس وربطه بدورة ولجنة.
- إنشاء اجتماع وربطه بحضور وقرارات ومرفقات.
- إنشاء سياسة مع إصدار معتمد وإصدار مسودة لاحق.
- إنشاء عقد مع تاريخ انتهاء وتنبيه.
- إنشاء مراسلة واردة وربطها برد أو عقد.
- إنشاء وثيقة سرية والتأكد من ربطها بالكيان الصحيح.

اختبارات الصلاحيات:

- مستخدم غير مصرح لا يستطيع عرض الإفصاحات أو ملفات الموظفين.
- مسؤول أرشيف يستطيع إدارة الوثائق والمراسلات ولا يستطيع اعتماد سياسة.
- سكرتير المجلس يستطيع إنشاء اجتماع وقرار ولا يستطيع نشر محتوى عام دون صلاحية.
- HR Officer يستطيع تعديل بيانات الموظفين ولا يستطيع تعديل قرارات المجلس إلا إذا منح صلاحية إضافية.
- Auditor يستطيع القراءة وفق نطاقه دون تعديل.

اختبارات سير العمل:

- لا يمكن اعتماد محضر اجتماع دون تاريخ وحضور ومحضر.
- لا يمكن نشر سياسة غير معتمدة.
- لا يمكن تعديل إصدار سياسة معتمد مباشرة.
- القرار المتأخر يظهر في قائمة المتابعة.
- العقد القريب من الانتهاء يظهر في التنبيهات.
- المراسلة بانتظار رد تظهر في تقرير المتأخرات عند تجاوز تاريخ الاستحقاق.

اختبارات التكامل:

- API أو طبقة بيانات الموقع العام لا ترجع إلا العناصر المنشورة والمعتمدة.
- تقارير الحوكمة تحترم الصلاحيات ولا تعرض ملفات حساسة.
- تغيير حالة سياسة من منشورة إلى مؤرشفة ينعكس على بيانات النشر.

اختبارات PostgreSQL:

- القيود المرجعية تمنع العلاقات اليتيمة.
- الفهارس تدعم البحث المتكرر حسب الحالة والتاريخ والجهة.
- الحقول الحساسة لا تكون قابلة للبحث العام إذا كانت السياسة تمنع ذلك.
- الحذف الناعم لا يكسر التقارير الأساسية.

## 10. معايير القبول العامة

- يمكن إدارة أعضاء المجلس ودوراته ولجانه من Filament مع سجل تاريخي واضح.
- يمكن إنشاء اجتماع كامل بمحضر وحضور وقرارات ومرفقات واعتماد.
- يمكن تتبع القرارات من الاعتماد حتى الإغلاق مع مسؤول وتاريخ استحقاق.
- يمكن إدارة السياسات بإصدارات وحالة اعتماد ونشر ومراجعة دورية.
- يمكن تسجيل المخاطر ومتابعة خطط المعالجة.
- يمكن تسجيل الإفصاحات وتقييد الوصول إليها حسب الصلاحيات.
- يمكن أرشفة الوثائق وتصنيفها والبحث عنها وربطها بالكيانات.
- يمكن إدارة المراسلات الواردة والصادرة والداخلية مع متابعة الردود.
- يمكن إدارة العقود والتنبيه قبل انتهائها وربطها بالمراسلات والوثائق.
- يمكن حفظ بيانات الموارد البشرية الأساسية وربط الموظفين بالمستخدمين والتكليفات.
- كل كيان حساس لديه Policy وصلاحيات واضحة وسجل تدقيق.
- التقارير المطلوبة يمكن استخراجها من البيانات دون معالجة يدوية كبيرة.
- الموقع العام لا يستهلك إلا بيانات منشورة ومعتمدة ومفلترة.
- لا توجد ملفات أو بيانات سرية مكشوفة لمستخدم غير مخول.

## 11. مراحل التنفيذ المقترحة

### المرحلة الأولى: الأساس والبيانات المرجعية

- تعريف الحالات الموحدة والتصنيفات ودرجات السرية.
- إنشاء كيانات الإدارات والمناصب والموظفين الأساسية.
- إنشاء دورات المجلس وأعضاء المجلس واللجان.
- إعداد الصلاحيات الأولية والأدوار.
- تجهيز سجل تدقيق للعمليات الحساسة.

مخرجات المرحلة:

- قاعدة بيانات جاهزة للحوكمة الأساسية.
- واجهات Filament للبيانات المرجعية والمجلس واللجان.
- صلاحيات قراءة وتعديل أولية.

### المرحلة الثانية: الاجتماعات والقرارات

- بناء إدارة الاجتماعات والحضور وجدول الأعمال.
- بناء القرارات والتوصيات والمتابعة.
- ربط الاجتماعات باللجان والمجلس.
- إضافة اعتماد المحاضر وسجل التحديثات.

مخرجات المرحلة:

- دورة اجتماع كاملة من الجدولة إلى الاعتماد.
- سجل قرارات قابل للتصفية والمتابعة.
- تنبيهات للقرارات المتأخرة.

### المرحلة الثالثة: السياسات والمخاطر والإفصاحات

- بناء إدارة السياسات والإصدارات.
- بناء سجل المخاطر.
- بناء الإفصاحات وتعارض المصالح.
- ربط السياسات والمخاطر والإفصاحات بالقرارات والعقود عند الحاجة.

مخرجات المرحلة:

- سياسات معتمدة بإصدارات محفوظة.
- سجل مخاطر قابل للتقرير.
- إفصاحات محمية بصلاحيات دقيقة.

### المرحلة الرابعة: الوثائق والمراسلات والعقود

- بناء الأرشيف المركزي للوثائق.
- بناء المراسلات الواردة والصادرة والداخلية.
- بناء العقود والاتفاقيات والتنبيهات.
- ربط المرفقات والوثائق بالكيانات الأساسية.

مخرجات المرحلة:

- أرشيف قابل للبحث والتصنيف.
- سجل مراسلات قابل للمتابعة.
- سجل عقود مع تواريخ وتنبيهات.

### المرحلة الخامسة: التكامل والتقارير والتحسين

- تجهيز نقاط قراءة للموقع العام للعناصر المنشورة.
- تجهيز مصادر بيانات التقارير.
- إضافة اختبارات التكامل والصلاحيات.
- مراجعة الأداء والفهارس وقيود PostgreSQL.
- تحسين تجربة Filament بناء على الاستخدام الفعلي.

مخرجات المرحلة:

- تكامل آمن مع Public Website.
- تقارير حوكمة وأرشيف وموارد بشرية أساسية.
- اختبارات تغطي المسارات الحرجة.

## 12. اعتبارات PostgreSQL

- استخدام قيود foreign keys لكل العلاقات الأساسية.
- استخدام enums أو جداول مرجعية للحالات حسب نمط المشروع المعتمد.
- إضافة فهارس على الحقول كثيرة التصفية مثل status وtype وdate وowner_id وdepartment_id.
- استخدام full text search أو فهارس مناسبة للبحث في الوثائق والمراسلات إذا أصبح الحجم كبيرا.
- حفظ التواريخ المهمة بصيغة timestamp مع timezone عند الحاجة.
- استخدام soft deletes للكيانات التي قد تحتاج استرجاعا أو تدقيقا.
- تصميم جداول pivot واضحة لعضويات اللجان والحضور والعلاقات بين الوثائق والكيانات.

## 13. حدود الملكية مع المسارات الأخرى

- مسار المالية يملك القيود المالية التفصيلية، بينما هذا المسار يحتفظ ببيانات العقود الإدارية والتواريخ والمرفقات.
- مسار المستفيدين والرعاية الاجتماعية يملك بيانات المستفيدين، بينما هذا المسار قد يربط مراسلة أو وثيقة بمستفيد دون تعديل بياناته الأساسية.
- مسار Public Website يملك العرض العام، بينما هذا المسار يحدد البيانات المعتمدة القابلة للنشر.
- مسار Reports يملك بناء التقارير النهائية ولوحات القياس، بينما هذا المسار يوفر البيانات والعلاقات والحالات اللازمة.
- مسار Foundation يملك المصادقة العامة والبنية المشتركة، بينما هذا المسار يطلب صلاحياته وسياساته الخاصة ضمن النظام العام.

## 14. الملفات المتوقع تعديلها عند التنفيذ لاحقا

هذه قائمة إرشادية للمطورين في مراحل لاحقة وليست تعديلا ضمن هذه المهمة:

- Models وMigrations للكيانات المذكورة.
- Filament Resources وصفحاتها.
- Policies لكل كيان حساس.
- Seeders للأدوار والحالات والتصنيفات.
- Tests للموارد والصلاحيات وسير العمل.
- Services أو Actions عند الحاجة للاعتماد، الأرشفة، إنشاء الإصدارات، والتنبيهات.
- API Resources أو Query classes لبيانات Public Website والتقارير.

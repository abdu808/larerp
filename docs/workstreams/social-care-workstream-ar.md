# خطة تنفيذ مسار المستفيدين والرعاية الاجتماعية

## 1. الهدف والنطاق

يهدف هذا المسار إلى بناء منظومة متكاملة لإدارة المستفيدين والأسر والحالات الاجتماعية داخل مشروع Laravel + Filament، بحيث تغطي دورة العمل من تسجيل المستفيد وجمع بياناته، مروراً بدراسة الحالة والزيارات الميدانية وطلبات المساعدة، وانتهاءً بالموافقات والصرف والمتابعة والتقارير.

يشمل النطاق:

- المستفيدون.
- الأسر والعلاقات الأسرية.
- مصادر الدخل.
- الالتزامات والمصاريف.
- الاحتياجات.
- دراسات الحالة.
- الزيارات الميدانية.
- طلبات المساعدة.
- الموافقات وسير العمل.
- الصلاحيات.
- الاختبارات.
- معايير القبول.
- التكامل مع المشاريع والمالية والمرفقات.

لا يشمل هذا المستند تنفيذ كود Laravel أو Filament، بل يحدد خطة العمل والمتطلبات الوظيفية والفنية المطلوبة للتنفيذ لاحقاً.

## 2. المبادئ العامة للتنفيذ

- اعتماد تصميم واضح يفصل بين بيانات المستفيد الأساسية، وبيانات الأسرة، ونتائج البحث الاجتماعي، وطلبات المساعدة.
- حفظ تاريخ التغييرات المهمة، خصوصاً في الحالة الاجتماعية، مستوى الاحتياج، حالة الاعتماد، وقرارات اللجان.
- دعم العمل الميداني عبر زيارات مجدولة ونتائج موثقة ومرفقات داعمة.
- ربط طلبات المساعدة بالمشاريع والميزانيات والقيود المالية عند الحاجة.
- جعل Filament واجهة تشغيل يومية سهلة للباحثين الاجتماعيين، المشرفين، لجان الاعتماد، والمالية.
- منع الوصول غير المصرح به إلى بيانات حساسة مثل الهوية، الدخل، التقارير الاجتماعية، والمرفقات الشخصية.

## 3. الكيانات الأساسية

### 3.1 المستفيدون

الغرض من كيان المستفيد هو تمثيل الشخص الذي يمكن أن يتلقى خدمات أو مساعدات مباشرة أو ضمن أسرة.

البيانات المقترحة:

- الاسم الكامل.
- رقم الهوية أو الإقامة أو الوثيقة.
- الجنسية.
- تاريخ الميلاد.
- الجنس.
- الحالة الاجتماعية.
- رقم الجوال.
- البريد الإلكتروني إن وجد.
- العنوان الوطني أو العنوان التفصيلي.
- المدينة والمنطقة والحي.
- حالة المستفيد: نشط، قيد المراجعة، موقوف، مؤرشف، متوفى.
- تصنيف المستفيد: فرد مستقل، رب أسرة، تابع، يتيم، أرملة، مريض، ذو إعاقة، كبار سن، غير ذلك.
- مستوى الأولوية أو درجة الاحتياج الحالية.
- ملاحظات عامة.

علاقات المستفيد:

- ينتمي إلى أسرة واحدة أو أكثر حسب سياسة النظام.
- لديه مصادر دخل.
- لديه التزامات.
- لديه احتياجات.
- لديه دراسات حالة.
- لديه زيارات ميدانية.
- يمكن أن يكون طرفاً في طلبات مساعدة.
- لديه مرفقات ومستندات إثبات.

### 3.2 الأسر

الغرض من كيان الأسرة هو تجميع المستفيدين المرتبطين اجتماعياً ومالياً، وتقييم احتياجهم كوحدة واحدة.

البيانات المقترحة:

- رقم ملف الأسرة.
- اسم الأسرة.
- رب الأسرة.
- عنوان الأسرة.
- عدد الأفراد.
- عدد المعالين.
- عدد العاملين.
- حالة السكن: ملك، إيجار، مع الأقارب، سكن خيري، غير مستقر.
- قيمة الإيجار إن وجدت.
- حالة الأسرة: قيد الدراسة، مؤهلة، غير مؤهلة، نشطة، موقوفة، مؤرشفة.
- درجة الاحتياج المحسوبة.
- الباحث الاجتماعي المسؤول.
- ملاحظات.

العلاقات:

- الأسرة تحتوي على عدة أفراد.
- الأسرة لها مصادر دخل والتزامات واحتياجات مجمعة.
- الأسرة لها دراسات حالة وزيارات ميدانية.
- الأسرة يمكن أن ترتبط بطلبات مساعدة جماعية.

### 3.3 العلاقات الأسرية

يجب توثيق علاقة كل فرد بالأسرة:

- رب أسرة.
- زوج أو زوجة.
- ابن أو ابنة.
- والد أو والدة.
- أخ أو أخت.
- قريب آخر.
- تابع غير قريب حسب سياسة الجمعية.

يجب تحديد:

- هل الفرد معال مالياً؟
- هل يقيم مع الأسرة؟
- هل لديه دخل مستقل؟
- هل له احتياجات خاصة؟

### 3.4 مصادر الدخل

الغرض منها بناء صورة مالية دقيقة للمستفيد أو الأسرة.

أنواع الدخل:

- راتب.
- تقاعد.
- ضمان اجتماعي.
- حساب المواطن أو دعم حكومي.
- أعمال حرة.
- تحويلات عائلية.
- إيجارات أو استثمارات.
- مساعدات دورية من جهات أخرى.
- دخل غير منتظم.

البيانات المقترحة:

- نوع الدخل.
- قيمة الدخل.
- دورية الدخل: شهري، ربع سنوي، سنوي، غير منتظم.
- مصدر الدخل.
- هل الدخل موثق؟
- تاريخ آخر تحقق.
- مرفق إثبات الدخل.
- ملاحظات.

### 3.5 الالتزامات والمصاريف

الغرض منها احتساب صافي الاحتياج وعدم الاكتفاء بإجمالي الدخل.

أنواع الالتزامات:

- إيجار.
- قروض.
- فواتير خدمات.
- علاج.
- تعليم.
- مواصلات.
- إعالة خارج الأسرة.
- أقساط.
- ديون موثقة.

البيانات المقترحة:

- نوع الالتزام.
- القيمة.
- الدورية.
- تاريخ البداية والنهاية إن وجدت.
- الجهة المستحقة.
- هل الالتزام موثق؟
- مرفق إثبات الالتزام.
- ملاحظات.

### 3.6 الاحتياجات

الغرض منها تسجيل الاحتياجات الاجتماعية والمالية والصحية والتعليمية والسكنية بشكل قابل للفرز والمتابعة.

أنواع الاحتياجات:

- غذاء.
- سكن.
- إيجار.
- علاج.
- أجهزة طبية.
- تعليم.
- كسوة.
- كفالة أيتام.
- ترميم منزل.
- أثاث.
- سداد فواتير.
- دعم موسمي.
- تمكين أو تدريب.

البيانات المقترحة:

- نوع الاحتياج.
- الوصف.
- درجة الإلحاح: منخفضة، متوسطة، عالية، حرجة.
- القيمة التقديرية.
- التاريخ المطلوب.
- الحالة: مفتوحة، قيد الدراسة، مغطاة جزئياً، مغطاة، ملغاة.
- الجهة أو المشروع المقترح للتغطية.
- مرفقات داعمة.

## 4. دراسات الحالة

تمثل دراسة الحالة التقييم الاجتماعي الرسمي للمستفيد أو الأسرة.

البيانات المقترحة:

- رقم الدراسة.
- المستفيد أو الأسرة.
- الباحث الاجتماعي.
- تاريخ فتح الدراسة.
- سبب فتح الدراسة: تسجيل جديد، تحديث دوري، طلب مساعدة، بلاغ، مراجعة أهلية.
- ملخص الحالة.
- الوضع السكني.
- الوضع الصحي.
- الوضع التعليمي.
- الوضع الوظيفي.
- الوضع المالي.
- مصادر الدعم الأخرى.
- المخاطر الاجتماعية.
- توصية الباحث.
- درجة الاحتياج الناتجة.
- حالة الدراسة: مسودة، قيد المراجعة، معتمدة، مرفوضة، تحتاج زيارة، مغلقة.
- تاريخ الاعتماد.
- المعتمد.

خطوات العمل المقترحة:

1. فتح دراسة حالة من ملف مستفيد أو أسرة.
2. جمع البيانات الأساسية والمالية والاجتماعية.
3. إرفاق المستندات الداعمة.
4. جدولة زيارة ميدانية عند الحاجة.
5. تسجيل نتائج الزيارة والتوصيات.
6. إرسال الدراسة للمراجعة.
7. اعتماد الدراسة أو إعادتها للتعديل.
8. تحديث درجة الاحتياج وحالة الأهلية.

قواعد مهمة:

- لا تعتمد دراسة حالة دون اكتمال الحد الأدنى من البيانات المطلوبة.
- يمكن للنظام طلب زيارة ميدانية تلقائياً عند وجود نقص أو تضارب في البيانات.
- يجب حفظ نسخة تاريخية من التوصية وقرار الاعتماد.

## 5. الزيارات الميدانية

الزيارات الميدانية أداة للتحقق من واقع الحالة وتحديث البيانات.

البيانات المقترحة:

- المستفيد أو الأسرة.
- دراسة الحالة المرتبطة.
- الباحث أو فريق الزيارة.
- تاريخ الزيارة المخطط.
- تاريخ التنفيذ الفعلي.
- نوع الزيارة: أولية، دورية، تحقق، طارئة، متابعة.
- حالة الزيارة: مجدولة، منفذة، لم يتم الوصول، مؤجلة، ملغاة.
- نتيجة الزيارة.
- ملاحظات السكن.
- ملاحظات الدخل.
- ملاحظات الأسرة.
- توصيات الزيارة.
- الموقع الجغرافي إن كان مناسباً.
- صور أو مستندات مرفقة.

متطلبات تشغيلية:

- عرض تقويم أو قائمة زيارات في Filament للباحثين.
- تنبيه الباحث بالزيارات القادمة والمتأخرة.
- منع اعتماد دراسة حالة تتطلب زيارة حتى يتم تسجيل نتيجة الزيارة.
- دعم إعادة جدولة الزيارة مع سبب التأجيل.

## 6. طلبات المساعدة

يمثل طلب المساعدة الإجراء التشغيلي الذي ينتج عنه تقديم دعم عيني أو مالي أو خدمي.

البيانات المقترحة:

- رقم الطلب.
- المستفيد أو الأسرة.
- نوع المساعدة.
- الاحتياج المرتبط.
- دراسة الحالة المرتبطة.
- المشروع أو البرنامج المرتبط.
- المبلغ أو القيمة التقديرية.
- الوصف.
- الأولوية.
- الحالة: مسودة، مقدم، قيد المراجعة، بانتظار اعتماد اجتماعي، بانتظار اعتماد مالي، معتمد، مرفوض، قيد الصرف، مصروف، مغلق، ملغى.
- سبب الرفض أو الإلغاء.
- تاريخ التقديم.
- مقدم الطلب.
- آخر جهة اعتمدت الطلب.
- مرفقات.

أنواع المساعدة:

- مالية مباشرة.
- سداد فاتورة أو التزام.
- سلة غذائية.
- علاج أو أجهزة طبية.
- إيجار أو سكن.
- تعليم.
- دعم موسمي.
- كفالة دورية.
- تمكين وتدريب.

قواعد العمل:

- لا ينتقل الطلب للاعتماد إلا إذا كان المستفيد أو الأسرة مؤهلاً حسب آخر دراسة حالة معتمدة.
- يجب ربط الطلب بمشروع أو بند مالي عند وجود أثر مالي.
- يجب منع تكرار طلبات متشابهة ضمن مدة محددة إلا بتجاوز صلاحية خاص.
- يجب إظهار سجل قرارات واضح لكل طلب.

## 7. الموافقات وسير العمل

يجب تصميم سير موافقات مرن قابل للتوسع حسب نوع المساعدة وقيمتها والمشروع المرتبط.

مراحل مقترحة:

1. إنشاء الطلب بواسطة الباحث أو موظف خدمة المستفيدين.
2. مراجعة اجتماعية من مشرف الرعاية.
3. اعتماد لجنة أو مدير عند تجاوز قيمة محددة.
4. مراجعة مالية للتحقق من الميزانية والبند.
5. اعتماد نهائي.
6. تنفيذ الصرف أو تسليم المساعدة.
7. إغلاق الطلب مع إثبات التنفيذ.

بيانات سجل الموافقة:

- الطلب المرتبط.
- المرحلة.
- صاحب القرار.
- القرار: اعتماد، رفض، إعادة للتعديل، تعليق.
- التعليق.
- التاريخ والوقت.
- المرفقات المرتبطة بالقرار إن وجدت.

قواعد مهمة:

- كل انتقال حالة يجب أن يكون مسجلاً.
- لا يسمح بتجاوز مرحلة إلا بصلاحية واضحة.
- يجب إتاحة إعادة الطلب للتعديل مع تعليق إلزامي.
- يجب فصل اعتماد الحالة الاجتماعية عن اعتماد الصرف المالي.

## 8. واجهات Filament المقترحة

### 8.1 موارد المستفيدين

- جدول قابل للبحث برقم الهوية، الاسم، الجوال، رقم ملف الأسرة.
- فلاتر حسب الحالة، المدينة، درجة الاحتياج، التصنيف.
- صفحات عرض تتضمن ملخصاً مالياً واجتماعياً.
- تبويبات للعائلة، الدخل، الالتزامات، الاحتياجات، الدراسات، الزيارات، الطلبات، المرفقات.
- إجراءات سريعة: فتح دراسة حالة، إنشاء طلب مساعدة، جدولة زيارة، إيقاف المستفيد، أرشفة.

### 8.2 موارد الأسر

- عرض أفراد الأسرة والعلاقات.
- ملخص دخل الأسرة والتزاماتها وصافي الاحتياج.
- سجل دراسات الحالة والزيارات والطلبات.
- إجراءات لإضافة فرد، نقل فرد، تحديث رب الأسرة، إعادة احتساب درجة الاحتياج.

### 8.3 موارد دراسات الحالة

- قائمة حسب الحالة والباحث وتاريخ آخر تحديث.
- نموذج منظم للأقسام الاجتماعية والمالية والصحية والتعليمية.
- إجراءات إرسال للمراجعة، اعتماد، رفض، طلب زيارة، إرجاع للتعديل.

### 8.4 موارد الزيارات الميدانية

- عرض الزيارات القادمة والمتأخرة والمنفذة.
- فلاتر حسب الباحث والحالة والتاريخ.
- نموذج نتيجة زيارة يدعم الملاحظات والمرفقات.
- إجراء إعادة جدولة مع سبب إلزامي.

### 8.5 موارد طلبات المساعدة

- جدول حسب الحالة والنوع والمشروع والقيمة.
- صفحة تفاصيل تعرض مسار الموافقة وسجل القرارات.
- إجراءات اعتماد ورفض وإعادة للتعديل وتحويل للمالية وإغلاق.
- تنبيهات للطلبات المتأخرة أو المعلقة في مرحلة اعتماد.

## 9. الصلاحيات والأدوار

الأدوار المقترحة:

- مسؤول النظام.
- مدير الرعاية الاجتماعية.
- مشرف اجتماعي.
- باحث اجتماعي.
- موظف خدمة مستفيدين.
- عضو لجنة اعتماد.
- موظف مالية.
- مدقق داخلي.
- قارئ تقارير.

أمثلة صلاحيات:

- إدارة المستفيدين: إنشاء، قراءة، تعديل، أرشفة.
- إدارة الأسر: إنشاء، قراءة، تعديل، نقل أفراد.
- إدارة الدخل والالتزامات: إنشاء، تعديل، حذف محدود، قراءة حساسة.
- إدارة دراسات الحالة: إنشاء، تعديل المسودات، مراجعة، اعتماد، رفض.
- إدارة الزيارات: جدولة، تنفيذ، تعديل النتيجة، إلغاء.
- إدارة طلبات المساعدة: إنشاء، مراجعة، اعتماد اجتماعي، اعتماد مالي، تنفيذ، إغلاق.
- عرض المرفقات الحساسة.
- تجاوز التكرار أو نقص البيانات.
- تصدير البيانات.

ضوابط حساسية البيانات:

- إخفاء بيانات الهوية والدخل عن الأدوار غير المخولة.
- تسجيل عمليات عرض أو تنزيل المرفقات الحساسة عند الحاجة.
- منع حذف السجلات التي لها قرارات أو صرف مالي، والاكتفاء بالأرشفة.

## 10. التكامل مع المشاريع

يجب ربط طلبات المساعدة بالمشاريع والبرامج الخيرية عند وجود مصدر تمويل أو حملة محددة.

نقاط التكامل:

- اختيار المشروع عند إنشاء طلب مساعدة.
- التحقق من أن نوع المساعدة مسموح ضمن نطاق المشروع.
- ربط الاحتياج ببند أو نشاط داخل المشروع.
- إظهار إجمالي الطلبات المرتبطة بالمشروع.
- دعم تقارير عدد المستفيدين والأسر حسب المشروع.
- منع اعتماد طلب على مشروع غير نشط أو خارج فترة التنفيذ.

مخرجات مفيدة للمشاريع:

- عدد المستفيدين المدعومين.
- إجمالي قيمة المساعدات.
- توزيع المساعدات حسب النوع.
- الحالات الحرجة التي تم تغطيتها.
- الطلبات المعلقة على المشروع.

## 11. التكامل مع المالية

يجب أن ينتقل الأثر المالي من طلب المساعدة إلى المالية بشكل منضبط، دون خلط بين قرار الاستحقاق الاجتماعي وقرار الصرف.

نقاط التكامل:

- ربط طلب المساعدة ببند مالي أو مركز تكلفة.
- التحقق من توفر الميزانية قبل الاعتماد النهائي.
- إنشاء التزام أو أمر صرف عند اعتماد الطلب المالي.
- تسجيل حالة الصرف: بانتظار الصرف، مصروف جزئياً، مصروف، فشل الصرف، ملغى.
- حفظ رقم العملية المالية أو سند الصرف.
- دعم المطابقة بين الطلبات المصروفة والسجلات المالية.
- منع إغلاق طلب مالي دون إثبات صرف أو سبب إلغاء.

قواعد مالية مقترحة:

- لا يتم الصرف دون اعتماد اجتماعي ومالي.
- لا يسمح بتعديل قيمة طلب معتمد مالياً إلا بإجراء تصحيحي واضح.
- يجب حفظ أثر تدقيق لكل تغيير في القيمة أو المشروع أو البند المالي.

## 12. التكامل مع المرفقات

المرفقات عنصر أساسي لإثبات الأهلية والاحتياج والتنفيذ.

أنواع المرفقات:

- هوية أو إقامة.
- كرت عائلة.
- إثبات سكن.
- عقد إيجار.
- تعريف راتب أو إثبات دخل.
- إثبات التزام أو فاتورة.
- تقرير طبي.
- تقرير مدرسي أو جامعي.
- صور زيارة ميدانية.
- محضر لجنة.
- إثبات صرف أو تسليم.

نقاط التكامل:

- ربط المرفقات بالمستفيد أو الأسرة أو الدراسة أو الزيارة أو طلب المساعدة.
- تصنيف المرفقات حسب النوع والحساسية.
- تحديد مرفقات إلزامية حسب نوع الطلب أو الدراسة.
- دعم انتهاء صلاحية بعض المستندات مثل عقد الإيجار أو التقرير الطبي.
- منع اعتماد الطلب عند نقص مرفقات إلزامية.
- تمكين المعاينة والتحميل حسب الصلاحيات.

## 13. الحوكمة وجودة البيانات

متطلبات جودة البيانات:

- منع تكرار المستفيدين حسب رقم الهوية أو الجوال أو تشابه الاسم مع تاريخ الميلاد.
- التحقق من اكتمال بيانات الأسرة قبل اعتماد دراسة حالة.
- تمييز البيانات غير الموثقة عن البيانات الموثقة.
- إظهار تنبيهات للبيانات القديمة التي تحتاج تحديثاً.
- دعم مراجعة دورية للأهلية كل فترة محددة.
- حفظ سبب الإيقاف أو الأرشفة.

مؤشرات تشغيلية:

- عدد الحالات قيد الدراسة.
- عدد الزيارات المتأخرة.
- عدد الطلبات المعلقة حسب المرحلة.
- متوسط زمن الاعتماد.
- نسبة الطلبات المرفوضة وأسبابها.
- إجمالي المساعدات حسب النوع والمشروع والمنطقة.

## 14. الاختبارات

### 14.1 اختبارات النماذج والعلاقات

- إنشاء مستفيد ببيانات صحيحة.
- منع تكرار رقم الهوية حسب السياسة المعتمدة.
- ربط مستفيد بأسرة.
- إضافة دخل والتزام واحتياج للمستفيد أو الأسرة.
- احتساب إجمالي الدخل والالتزامات وصافي الاحتياج.
- التأكد من أن حذف أو أرشفة السجلات المرتبطة لا يكسر العلاقات.

### 14.2 اختبارات سير دراسة الحالة

- إنشاء دراسة حالة كمسودة.
- منع إرسال الدراسة للمراجعة عند نقص بيانات إلزامية.
- إرسال الدراسة للمراجعة.
- إرجاع الدراسة للتعديل مع تعليق إلزامي.
- اعتماد الدراسة وتحديث أهلية المستفيد أو الأسرة.
- طلب زيارة ميدانية قبل الاعتماد عند الحاجة.

### 14.3 اختبارات الزيارات الميدانية

- جدولة زيارة لباحث.
- تسجيل نتيجة زيارة.
- منع إغلاق زيارة منفذة دون نتيجة.
- إعادة جدولة زيارة مع سبب.
- ربط مرفقات الزيارة بسجل الزيارة.

### 14.4 اختبارات طلبات المساعدة

- إنشاء طلب مساعدة من احتياج قائم.
- منع الطلب عند عدم وجود دراسة حالة معتمدة إذا كانت مطلوبة.
- منع تكرار طلب مشابه ضمن المدة المحددة.
- تمرير الطلب عبر مراحل الموافقة.
- رفض الطلب مع سبب إلزامي.
- تحويل الطلب للمالية بعد الاعتماد الاجتماعي.
- تحديث حالة الطلب بعد الصرف.

### 14.5 اختبارات الصلاحيات

- الباحث يرى الحالات المسندة له فقط إذا كانت السياسة تتطلب ذلك.
- المشرف يمكنه مراجعة واعتماد الدراسات ضمن نطاقه.
- المالية ترى بيانات الطلبات المالية دون تعديل التقرير الاجتماعي إلا بصلاحية.
- عضو اللجنة يستطيع اتخاذ قرار في مرحلة اللجنة فقط.
- المستخدم غير المخول لا يستطيع عرض المرفقات الحساسة.

### 14.6 اختبارات التكامل

- ربط طلب مساعدة بمشروع نشط.
- منع ربط الطلب بمشروع غير نشط.
- التحقق من الميزانية عند الاعتماد المالي.
- إنشاء أثر مالي أو مرجع صرف بعد الاعتماد.
- إرفاق إثبات الصرف وإغلاق الطلب.
- ظهور الطلبات المرتبطة في تقارير المشروع والمالية.

## 15. معايير القبول

يعد المسار مقبولاً عند تحقق المعايير التالية:

- يمكن تسجيل مستفيد وأسرة وربط الأفراد بعلاقات أسرية واضحة.
- يمكن تسجيل الدخل والالتزامات والاحتياجات مع مرفقات داعمة.
- يمكن فتح دراسة حالة وإكمالها ومراجعتها واعتمادها وفق صلاحيات واضحة.
- يمكن جدولة زيارة ميدانية وتوثيق نتائجها وربطها بالدراسة.
- يمكن إنشاء طلب مساعدة وربطه باحتياج ودراسة حالة ومشروع عند الحاجة.
- يمر طلب المساعدة بسير موافقات واضح مع سجل قرارات كامل.
- لا يتم الصرف إلا بعد الاعتماد الاجتماعي والمالي.
- تظهر حالات الطلب والدراسة والزيارة بشكل مفهوم في واجهات Filament.
- تمنع الصلاحيات الوصول أو التعديل غير المصرح به للبيانات الحساسة.
- تعمل اختبارات العلاقات وسير العمل والصلاحيات والتكامل بنجاح.
- يمكن استخراج تقارير تشغيلية أساسية عن المستفيدين والطلبات والمساعدات.
- يمكن ربط المرفقات بكل كيان ذي صلة مع ضبط الأنواع والحساسية.

## 16. مراحل التنفيذ المقترحة

### المرحلة الأولى: الأساس

- تصميم نماذج المستفيدين والأسر والعلاقات الأسرية.
- تحديد حالات المستفيد والأسرة.
- بناء موارد Filament الأساسية للمستفيدين والأسر.
- إضافة صلاحيات القراءة والإنشاء والتعديل الأساسية.
- إضافة اختبارات العلاقات ومنع التكرار.

### المرحلة الثانية: التقييم المالي والاجتماعي

- إضافة الدخل والالتزامات والاحتياجات.
- بناء ملخص مالي للمستفيد والأسرة.
- دعم المرفقات الأساسية.
- إضافة قواعد اكتمال البيانات.
- إضافة اختبارات الاحتساب والتحقق.

### المرحلة الثالثة: دراسات الحالة والزيارات

- بناء دورة دراسة الحالة.
- إضافة الزيارات الميدانية وجدولتها ونتائجها.
- ربط الدراسة بالزيارة والمرفقات.
- إضافة موافقات الدراسة.
- إضافة اختبارات سير الدراسة والزيارة.

### المرحلة الرابعة: طلبات المساعدة والموافقات

- بناء طلبات المساعدة وربطها بالاحتياجات.
- تصميم سجل الموافقات والانتقالات.
- إضافة صلاحيات اللجنة والمشرفين.
- منع التكرار وضبط الشروط.
- إضافة اختبارات سير طلبات المساعدة.

### المرحلة الخامسة: التكامل المالي والمشاريع

- ربط الطلبات بالمشاريع والبرامج.
- ربط الطلبات بالبند المالي أو مركز التكلفة.
- إضافة تحقق الميزانية وحالة الصرف.
- دعم إثبات الصرف والإغلاق.
- إضافة اختبارات التكامل والتقارير.

### المرحلة السادسة: التقارير والتحسين

- بناء لوحات متابعة للرعاية الاجتماعية.
- إضافة مؤشرات الأداء والتأخير.
- تحسين البحث والفلاتر والتصدير.
- مراجعة صلاحيات البيانات الحساسة.
- إضافة اختبارات قبول شاملة.

## 17. مخاطر واعتبارات

- حساسية بيانات المستفيدين تتطلب صلاحيات دقيقة وسجل تدقيق مناسب.
- سوء جودة البيانات قد يؤدي إلى قرارات دعم غير دقيقة.
- تداخل الاعتماد الاجتماعي والمالي قد يسبب أخطاء تشغيلية، لذلك يجب الفصل بينهما.
- كثرة حالات الاستثناء تتطلب سياسة واضحة للتجاوزات.
- المرفقات قد تصبح كبيرة أو حساسة، لذلك يجب تحديد سياسة تخزين ووصول واحتفاظ.
- التكامل مع المالية والمشاريع يجب أن يكون واضح الحدود لتجنب ازدواجية السجلات.
